## 1. 제1장: 플랫폼 아키텍처 개요 및 3대 메가 플랫폼 통합 철학

### 1) 3대 메가 플랫폼 삼각 편대(Tri-Platform Architecture)
전사 복지·안전망 아키텍처는 취약계층의 발굴에서부터 심층 판정, 그리고 24시간 상시 관제 및 비상 출동에 이르는 전 생애주기를 3개의 유기적 서브시스템으로 분할하여 상호 연동합니다.

│                                                                             │

│    - 노인일자리 참여자(2인 1조)가 어르신 가구 방문                            │
│    - 단일행 하이브리드 관리번호 채번 + 15문항 단축 우울척도 선별검사        │
│    - 전자서명 수집 + TLS 1.3 암호화 채널로 에지 전송 (클라이언트 무부하)     │

│    - RFC 6238 TOTP 10분 일회성 오프라인 도어락 개방 + 현장 바디캠 실시간관제 │

## 3. 제3장: 에지 제로트러스트 PII 가명화/암호화 및 동적 마스킹 거버넌스

### 1) 제로트러스트 에지 인메모리 암호화 라이프사이클
- **클라이언트 무부하 전송**: S-GDS PWA 모바일 기기는 무거운 클라이언트 사이드 암호화 연산 없이, 표준 HTTPS(TLS 1.3) 전송 구간 암호화를 통해 API Gateway(Cloudflare Workers)로 데이터를 전송합니다.
- **Workers 에지 인메모리 암호화**: Workers 수신 즉시 Web Crypto API의 `AES-256-GCM` 대칭키 암호화를 실행하여 개인식별정보(PII: 성명, 연락처, 상세주소, 병력 등)를 암호화합니다.
- **평문 메모리 즉시 소멸**: 암호화 직후 메모리 내의 원본 평문 문자열은 가비지 컬렉션을 통해 즉시 소각됩니다.
- **D1 완전 암호문 저장**: Cloudflare D1 RDBMS에는 `enc_name`, `enc_phone`, `enc_detail_address`, `enc_health_notes` 등의 암호문(Base64)만 INSERT되므로, DB 파일 전체가 물리적으로 유출되더라도 원본 식별이 원천 차단됩니다.

### 2) 암호화 알고리즘 상세 규격
- **대칭키 암호화**: `AES-256-GCM` (NIST SP 800-38D 준수)
  - 마스터 키: 256비트 (32바이트) - Cloudflare Dashboard Environment Secrets 주입
  - 초기화 벡터(IV): 96비트 (12바이트) 난수 (`crypto.getRandomValues`)
  - 무결성 인증 태그: 128비트 (16바이트) MAC 태그
  - 패킹 스트링: `[IV (12B)] + [Ciphertext] + [AuthTag (16B)] ➔ Base64`
- **검색 지원용 단방향 해시**: `hash_phone_search`
  - 암호화된 전화번호 컬럼에 대해 동등 일치(`WHERE phone = ?`) 검색을 지원하기 위해, 전사 공통 비밀키를 결합한 `HMAC-SHA256` 256비트 Hex 해시를 별도 컬럼에 병렬 저장합니다.

### 3) 동적 마스킹(Dynamic Masking) 및 공직자 메일(@korea.kr) OTP 2차 인증
- **원칙**: 관리자 화면 조회 시 Cloudflare Worker가 메모리에서 일시 복호화 후, 권한에 맞추어 마스킹된 형태로만 JSON 응답을 클라이언트에 내려줍니다.
- **마스킹 규칙**:
  - 성명: 2자 `홍*`, 3자 `홍*동`, 4자 이상 `남***우`
  - 전화번호: `010-****-1234` (휴대폰), `02-***-5678` (유선)
  - 상세주소: 읍면동 도로명까지 표출, 동·호수는 `***호` 마스킹
- **공직자 메일(@korea.kr) 2차 OTP 인증 및 감사로그**:
  - 지자체 공무원이 행복e음 등록 등을 위해 원본 복호화나 실명 엑셀 반출을 요청할 경우, 사전에 승인된 공직자 메일(`@korea.kr`)로 3분 유효 6자리 일회성 난수 OTP를 전송합니다.
  - OTP 통과 시에만 세션 메모리에서 10분간 원본 복호화를 일시 허용하며, `audit_logs` 테이블에 열람자, 대상자, 일시, 사유, SHA-256 체크섬을 영구 보존합니다.

### 4) 지자체 현장 페이퍼(종이) 명단 대응 듀얼 프라이버시 모드 (Dual Privacy Mode)
- **현장 실무 현실**: 동 행정복지센터는 사전 개인정보 수집·동의서를 징구한 후, 노인인력개발센터(수행기관)에 전산 파일 대신 직인 찍힌 종이 명단을 교부하며, 참여자 배부 명단은 월말 실적 제출 시 전량 회수 파기합니다.
- **아키텍처 대응**: 본 시스템은 B안을 상위 집합(Superset)으로 구축하여, 지자체의 요구 성향에 따라 단 하나의 설정 플래그(`privacy_policy_mode`)로 즉시 스위칭되는 듀얼 모드를 지원합니다.
  - `ENCRYPTED_PII (B안 표준)`: 인적사항 1회 등록 ➔ Workers 에지 AES-256-GCM 암호화 ➔ 상시 마스킹 ➔ 공직자 메일 OTP 복호화.
  - `ZERO_PII (A안 스위칭)`: 종이 명단 번호대로 UID만 등록 ➔ DB에 PII 완전 미저장(NULL/가명) ➔ 순수 UID와 임상 설문 점수로만 운영.
- **효과**: 향후 지자체가 "서버에 이름/전화번호 1글자도 올리지 마라(A안)"고 요구하더라도, 단 1줄의 코드나 스키마 수정 없이 즉각 수용하여 개발/운영 피로도를 0으로 유지합니다.

## 4. 제4장: Check24h 24시 상시 관제 및 오프라인 스마트도어락 물리보안

### 1) 24시간 실시간 무자각 센싱 및 관제망
- **mmWave 레이더**: 비접촉 마이크로웨이브를 통해 어르신의 흉부 미세 움직임을 포착하여 호흡수/심박수/체류 위치를 실시간 계측.
- **스마트 도어센서**: 냉장고, 화장실, 현관문 개폐 이벤트를 감지하여 12시간/24시간 이상 미활동 시 즉시 이상 징후 감지.
- **경보 브로드캐스팅**: WebSockets(WSS) 및 Web Push(VAPID)를 통해 지자체 관제 콘솔 및 현장 Spoke 출동대원 단말에 1초 이내 팝업 전달.

### 2) RFC 6238 TOTP 오프라인 스마트도어락 개폐 제어망
위급 상황 발생 시 출동대원이 댁내로 신속히 진입할 수 있도록 인터넷 단선 환경에서도 작동하는 오프라인 마스터 OTP 발급 체계를 가동합니다.
- **알고리즘**: `RFC 6238 TOTP (Time-Based One-Time Password)` + `HMAC-SHA256`.
- **타임 스텝**: 600초 (10분 유효). 출동 및 현장 도착 지연을 고려하여 10분 카운트다운 적용.
- **오프라인 검증 원리**:
  - 각 도어락 내부의 보안 칩(SE)과 서버의 D1에 동일한 고유 시드 솔트(`doorlock_salt`, AES-256-GCM 암호화 보관)가 동기화되어 있습니다.
  - 가구 인터넷이나 전원이 끊긴 오프라인 상태에서도 도어락의 자체 RTC(실시간 시계)와 SE 칩이 서버와 동일한 6자리 비밀번호를 계산하여 문을 개방합니다.
  - 출동 종료 즉시 해당 OTP는 만료되며 재사용 공격(Replay Attack)을 차단합니다.

   - 엑셀 다운로드 시 공공 보안 규격에 맞추어 시트 잠금 및 PDF 열기 비밀번호 암호화(`123456`)를 백그라운드 적용합니다.
3. **전사 실무 권한 통제 시스템 (RBAC Granular Matrix)**:
   - **기본 실무 권한 (`permissions`)**:
     * `READ_WRITE` (읽기+쓰기): 대상자/조사 원장 조회 및 신규 등록, 정보 수정, 상담일지 작성 등 실무 총괄 권한.
     * `READ` (읽기 전용): 대상자 명부 및 서식/통계 조회만 허용하며, 등록·수정·삭제 버튼이 자동 차단됨 (감사/모니터링용).
     * `WRITE` (쓰기 전용): 현장 방문 조사지 및 상담일지 등록/수정 전담.
   - **특수 보안 권한 (`can_export_excel`, `can_unmask`)**:
     * `can_export_excel`: 17열 대용량 엑셀 원장 다운로드 권한 (기본값: false, 인가된 관리자만 허용).
     * `can_unmask`: 주민등록번호/연락처 등 민감 개인정보 마스킹 해제 권한 (기본값: false, 해제 시 사유 필수 입력 및 audit_logs 기록).

## 5. 제5장: 공공 행정 표준 A4 PDF 인쇄 엔진 & 대용량 엑셀(ExcelJS) 17열 대장 규격

본 장은 지자체, 보건복지부 및 공공기관에 제출되는 법적 행정 서식과 대량 데이터 반출의 무결성을 보장하기 위한 전사 절대 표준입니다.

### 1) 📄 공공 행정 제출용 표준 A4 PDF 인쇄 엔진 (html2pdf / 벡터 렌더링)
1. **물리 규격 고정**:
   - 브라우저 캡처 방식의 해상도 저하와 뭉개짐을 차단하기 위해 인쇄 전용 컨테이너 폭을 **`width: 730px; margin: 0 auto;`**로 물리적 강제 고정합니다.
   - A4(297mm ≈ 1,122px) 기준, 상하좌우 마진(`margin: [10, 5, 5, 5]mm`) 적용 시 인쇄 가용 높이는 약 **1,065px**입니다.
2. **A4 1장/2장 완결형 디자인 표준**:
   - 좁은 테이블 패딩(7~9px)을 엄금하고, 셀 내부 **`padding: 11px ~ 13.5px 8px`**를 적용하여 글자 겹침을 방지하고 상하 공간을 조화롭게 채워 여백으로 인한 불필요한 다음 페이지 넘어감을 원천 차단합니다.
   - 한글 단어 쪼개짐 방지(`word-break: keep-all;`)를 전면 적용합니다.
3. **서식 단독 분리 다운로드 원칙**:
   - 업무 성격과 보관 주기가 다른 서식(예: '노인우울척도 검사지', '고독사 예방 조사표', '개인정보 수집·이용 동의서')은 억지로 1개 PDF 파일에 결합하지 않고, **각각 단독 A4 1장 전용 다운로드 버튼으로 완전 분리**합니다.
4. **전자서명 이미지 비동기 무결성 보장**:
   - 현장 전자서명 캔버스 이미지(DataURL/WebP)가 PDF 생성 시 투명화되거나 누락되지 않도록 반드시 `img.onload` 완료 비동기 대기 후 PDF 변환을 트리거합니다.
5. **행정 보안 열기 비밀번호 암호화 거버넌스**:
   - **현재 개발 및 테스트 단계**: 전사 공통 행정 보안 열기 비밀번호 **`123456`**을 백그라운드 적용합니다.
   - **향후 지자체 운영 확산 단계**: 지자체 공무원 및 담당 관리자만 열람할 수 있도록 **[지자체 행정코드(5자리) + 대상자 관리번호 뒷자리(3자리) = 8자리 고유 동적 암호(예: `28260001`)]**로 무중단 전환합니다.
   - **단말기 화면 노출 원천 금지**: 단말기 분실/노출에 따른 개인정보 유출을 방지하기 위해 화면 토스트나 UI에 비밀번호를 일체 표기하지 않는 무자각 백그라운드 암호화 원칙을 엄수합니다.

### 2) 📊 공공 행정 표준 17열 엑셀(ExcelJS) 대장 규격
1. **정부·지자체 17열 공식 스키마**:
   - 컬럼 구성: `순번 | 문서UID | 대상자UID | 참여자UID | 지역 | 성명 | 생년월일 | 성별 | 나이 | 주소 | 연락처 | 동거형태 | 우울점수 | 고위험여부 | 조사자 | 의뢰처 | 조사일자`
2. **시트 보호 및 위변조 방지**:
   - 공식 대장 반출 시 시트 보호 암호(`sheet.protect('123456')`)를 백그라운드 적용하여 무단 셀 수정을 차단합니다.
3. **컬럼 너비 자동 맞춤 (Auto-Fit)**:
   - 관리번호, 연락처, 주소가 2줄로 꺾이거나 잘리지 않도록 데이터 길이에 따른 mm 단위 컬럼 너비 강제 제어 규격을 준수합니다.
4. **수치 1:1 결합 정합성**:
   - 엑셀 상단 총괄표 건수와 하단 상세 데이터 행 수가 1:1로 완벽하게 일치해야 하며, 불필요한 디버그용 JSON 다운로드를 원천 금지합니다.

## 6. 제6장: 엔터프라이즈 UI/UX 디자인 시스템 & 중앙 정렬 페이지네이션 통일 규격

본 장은 전사 플랫폼의 시각적 품격과 사용자 경험의 통일성을 위한 절대 표준 가이드라인입니다.

### 1) 모던 슬레이트(Slate) 컬러 시스템 (과도한 원색 배제)
- 시각적 피로도를 유발하는 쨍한 원색(순수 빨강, 순수 파랑, 순수 노랑)의 혼합 사용을 엄격히 금지합니다.
- 차분하고 신뢰감을 주는 모던 슬레이트(Slate) 계열을 기본 톤앤매너로 구성합니다:
  - **배경 및 카드**: `#f8fafc` (Slate 50), `#ffffff` (Pure White), `#f1f5f9` (Slate 100)
  - **헤더 및 본문 텍스트**: `#0f172a` (Slate 900 - 순수 블랙 대비 부드러운 가독성 제공)
  - **보조 설명 및 레이블**: `#475569` (Slate 600)
  - **메인 브랜드 및 액션 버튼**: `#1e293b` (다크 네이비) 또는 차분한 `#2563eb` (로열 블루)
  - **상태 배지(성공/주의/경고)**: 파스텔 톤 배경 + 정돈된 텍스트 조합 준수

### 2) 타이포그래피 표준
- 웹 및 모바일 인터페이스: `Pretendard`, `system-ui`, `-apple-system`, `sans-serif`
- 관공서 서식 및 행정 출력물: `맑은 고딕 (Malgun Gothic)`

### 3) CSS 스타일링 원칙 (!important 남발 엄단)
- 단순 스타일 충돌을 덮기 위한 `!important` 선언의 남발을 엄격히 금지합니다.
- 부모-자식 셀렉터와 명확한 클래스 네이밍 기반의 정석적인 CSS 명시도(Specificity) 구조를 설계합니다.
- 공통 클래스(`form-group`, `form-label`, `filter-ctrl`, `btn-action`)를 일관되게 재사용합니다.

### 4) 🔢 테이블 페이지네이션 전사 통일 표준 (Center-Aligned Pagination)
모든 관리자 테이블(수혜자 카드, 연계 관리, 사업단 관리, 통계 대시보드 등)의 하단 페이지네이션은 예외 없이 다음 표준 규격을 준수합니다:

1. **배치**:
   - 양 끝 분리(`justify-content: space-between`)를 전면 폐기하고, **화면 정중앙 일렬 정렬(`display: flex; justify-content: center; align-items: center; gap: 16px;`)**을 준수합니다.
2. **중앙 일렬 요소 구성 (좌 ➔ 우)**:
   - **총 건수 표출**: `총 N건 (X~Y 표시)` (색상: `#64748b`, 폰트: 12px)
   - **내비게이션 버튼 바**:
     `[처음 <<]` ➔ `[< 이전]` ➔ `[ 1 ] [ 2 ] [ 3 ] [ 4 ] [ 5 ]` ➔ `[다음 >]` ➔ `[>> 마지막]`
     - 현재 페이지 버튼: `background: #0f172a; color: #ffffff; font-weight: 700;` (`active` 클래스)
     - 비활성 버튼(1페이지일 때 처음/이전, 마지막 페이지일 때 다음/끝): `disabled` 및 `opacity: 0.4`
   - **페이지당 보기 개수 셀렉트박스**:
     `[10개씩 보기 / 20개씩 보기 / 30개씩 보기]` (`height: 28px; font-size: 11.5px;`)
3. **단일 페이지(1페이지만 존재) 시 동작**:
   - 데이터가 1페이지만 있을 때 불필요한 `« ‹ › »` 비활성화 화살표를 숨기고 숫자 `[1]`만 단정하게 중앙에 표출합니다.

### 5) 텍스트 및 인터페이스 표현 가이드라인 (이모티콘 과용 지양)
- 공공 복지안전망 시스템의 품격과 전문성을 위해 공식 공문서, 행정 서식, 관리자 화면 및 코드 주석에서 무분별한 이모티콘 사용을 전면 배제합니다.
